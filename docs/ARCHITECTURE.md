# Архитектура

## Принципы

- Desktop-first, локальное выполнение, без облачных зависимостей.
- Исходная STL-поверхность является неизменяемым источником геометрии.
- Метки хранятся отдельно от геометрии и индексируются по исходным треугольникам.
- Проект привязан к fingerprint упорядоченных координат вершин и connectivity.
- Семантическая разметка отделена от будущего геометрического выравнивания.

## Слои

- `core.mesh`: импорт STL, триангуляция при чтении, fingerprint, центры граней.
- `core.labels`: идентификаторы классов и цвета.
- `core.project`: версия формата проекта, сохранение и проверка источника.
- `core.export`: экспорт обучающих массивов и метаданных.
- `ui.main_window`: Qt-интерфейс и 3D viewport.

## Формат меток

Один uint8 на каждую грань исходной треугольной сетки. ID 0–4 определены в `core.labels`.

Проект JSON хранит имя исходного STL, SHA-256 fingerprint геометрии, число вершин и граней, а также массив меток.

Экспорт NPZ содержит:
- `vertices`: N×3 float32;
- `faces`: F×3 int32;
- `face_labels`: F uint8.

JSON рядом с NPZ содержит fingerprint, кодировку классов и количество граней каждого класса.

## Будущая AI-подсистема

Annotator должен производить проверяемую разметку, пригодную для обучения. Выбор PointNet++/PointNeXt или mesh-based архитектуры будет сделан после сбора и анализа репрезентативных размеченных сканов. Данные разделяются по исходным протезам, а не по случайным фрагментам одного скана.

## Ограничения текущего прототипа

Первая реализация кисти использует евклидово расстояние между центрами граней. Это базовый инструмент первичной разметки, не геодезическая кисть по поверхности. Для тонких/близко расположенных участков потребуется surface-aware brush, ограничение связностью и undo/redo.
